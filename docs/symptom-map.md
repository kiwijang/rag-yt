# 平面肌肉地圖

登入後從工作區導覽「平面肌肉地圖」進入 `/symptom-map`。此頁屬於既有 Nx / Angular 應用程式的 lazy route，沿用登入保護、共用寬度、字體及導覽；不新增後端 API 或資料表。

## 選取流程

1. **症狀大區**：用原創 SVG 人體色塊或清單，選擇頭頸、上背／肩／上臂、前臂／手、軀幹、下軀幹、髖／大腿／膝、小腿／踝／足。
2. **細部位置**：只有選定大區後才顯示該區 3 個疼痛位置；可切換正背面，從圖上編號或清單選取。
3. **相關肌肉**：選定疼痛位置後才列出參考來源的主要／次要關聯肌肉，選一個肌群後，再選模型的左右側或肌肉分部。
4. **後續操作**：選到實際模型部件後才能「在 3D 中定位」。也可將所選肌肉名稱帶入 LLM 草稿或 RAG 搜尋，不自動送出查詢／推論。

切換上層選項會清空下層選擇。可用步驟列、更換位置、返回全身區域或重新選擇回到前面。選定區域、位置或肌肉後，焦點會移到下一個面板，手機版會捲動到新選項；尊重 reduced-motion 設定。

## 參考來源與範圍

流程參考 [The Trigger Point & Referred Pain Guide](https://www.triggerpoints.net/) 的 Select Symptom Area → 症狀大區 → 細部症狀 → 肌肉頁。2026-11-16 選取並核對 21 個常見疼痛位置的關聯資料，合計 70 個雙語肌群條目；這是選定範圍，未宣稱涵蓋整站的全部症狀。

人體輪廓、色塊、位置示意與版面由本專案繪製，未複製來源網站圖片、疼痛分布圖、激痛點圖、說明文章或 image-map 座標。頁面對每個症狀、肌肉與大區提供來源連結。編號僅為區域位置示意，並非激痛點座標；足底中段以足部標記示意。

症狀對肌肉的關聯沿用來源的主要／次要分組，不以模型鄰近位置推導，也不是 AI 即時產生。這些內容供查閱，不應單憑疼痛位置判斷病因。

這裡的 7 個「症狀大區」與 3D 的 6 個 `trigger-point` 解剖分類用途不同；沒有覆寫 `Zone_*`，也不會將新症狀分類存入資料庫。

| 症狀大區 | 收錄的細部疼痛位置 |
| --- | --- |
| 頭頸 | 後腦、頸後、太陽穴 |
| 上背、肩與上臂 | 肩前側、肩後側、上臂前側 |
| 前臂與手 | 肘外側、肘內側、手腕／手掌側 |
| 軀幹 | 前胸、側胸、腹部 |
| 下軀幹 | 腰部、臀部、鼠蹊部 |
| 髖、大腿與膝 | 大腿前側、髖／大腿外側、膝前側 |
| 小腿、踝與足 | 小腿後側、足跟、足底中段 |

## 模型對應

`symptom-map-data.ts` 使用明列的英文名稱／分部對照，對接活躍模型目錄的真實 FJ／TP／ZA ID。選單僅提供肌肉，排除骨骼、支持結構及已有細分模型的整組重疊網格。肌群可對應多個部件，例如三角肌三個分部、肱二頭肌長短頭、枕下肌群四個肌肉，各自保留左右側。

三個來源條目目前沒有精確模型：`pectoralis-minimus`、`semispinalis-capitis`、`sternalis`。頁面明確顯示未對應，停用 3D 定位；不把 Pectoralis Minimus 換成名稱不同的胸小肌，也不把未細分的半棘肌當作頭半棘肌。仍可開啟來源、帶入對話或檢索。

對應期間也修正 `Tensor fasciae latae`（闊筋膜張肌）因字串含 fascia 被誤歸支持結構的問題。之後依 Startup.blend 進行來源權威整理，目前為 466 個肌肉、238 個骨骼與 8 個筋膜相關支持結構，共 712 個物件。31 個移除的舊 ID 有定位對照，詳見 [Startup 肌肉整理](startup-muscle-reconciliation.md)。

3D 定位使用 `/muscles?id=FJ...&view=front` 或 `id=TP:...`。3D 頁驗證 ID 存在後才設定選取，正背面只接受 front/back。模型載入完成後會以所選肌肉的世界座標包圍盒置中並縮放，切換定位 ID 或正背面時重新聚焦；一般手動旋轉不會被持續拉回。清單按鈕、模型點選與定位連結共用 select()，其他肌肉預設為 20% 不透明度，所選肌肉維持 100% 高亮；可用既有透明度滑桿調整，或按「一鍵復原模型」恢復一般顯示。

## 檔案與更新

- `frontend/apps/frontend/src/app/pages/symptom-map-page/symptom-map-page.component.ts`：逐層狀態、條件顯示、重選、詳細部件與跨頁操作。
- 同目錄 `flat-body-map.component.ts`：可鍵盤操作的 SVG 大區色塊、正背面、縮放與位置編號。
- 同目錄 `symptom-map-data.ts`：區域、中文標籤、原創位置座標及肌群到實際模型的名稱對照。
- 同目錄 `symptom-relations.generated.ts`：核對過的靜態關聯快照，每條症狀記錄都有 sourceUrl；不在瀏覽器執行爬取。

擴充位置時需先核對來源，新增明確的中文名稱／關聯，並確認各肌群能對應實際模型或顯示未對應。資料不會隨來源網站自動更新。

## 驗證

- `node tests/SymptomMap.Checks/check-data.cjs`：7 區、21 位置、70 肌群；來源 URL、名稱、唯一性、類型、真實模型 ID，以及三個未對應項目。
- `tests/SymptomMap.Checks/check-ui.cjs`：Playwright 使用實際頁面測試逐層顯示、21 條路徑、SVG 鍵盤、重置、缺模型、左右側／分部、手機版、深色模式、登入保護與實際 3D 定位。
- 測試確認開啟與操作平面頁不請求 GLB，也不呼叫 `/api/`；只有使用者按 3D 定位才載入 3D 資產。
- `tests/Anatomy.Checks/check-startup.mjs`：闊筋膜張肌分類修正後，逐頂點確認模型幾何未變。
- 在 `frontend` 執行 `npx nx build frontend --skip-nx-cache` 完成正式建置。

Playwright 測試可透過 `PLAYWRIGHT_MODULE` 指向已安裝的 Playwright 套件；使用 Chrome 的軟體 WebGL，不執行 GPU 模型推論。
